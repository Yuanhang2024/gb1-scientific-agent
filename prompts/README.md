# 科学智能体提示词

## 使用方式

- [legacy-v1.txt](<legacy-v1.txt>) 保存首轮提示，供复现与比较。
- [scientific-v2.txt](<scientific-v2.txt>) 用于三种子提示与约束对照；实测出现了复制预填候选的行为，结果保留用于分析。
- [scientific-v3.txt](<scientific-v3.txt>) 是自主设计试验版：首答不提供随机候选名单，纠正阶段才给替补，并保留科研假设和反馈结构。
- [优化依据与验证方案](<../提示词优化依据与验证.md>) 记录来源、研究要求、改动与比较条件；[对照结果](<../提示词对照结果.md>) 记录实际观察。

运行自主设计版时显式指定 `--prompt-profile v3`。默认仍为 v1，以保证已有命令和运行记录的含义稳定。每次新实验使用独立输出目录；程序会拒绝在同一记录中混合提示版本或不同的提示文本。

## 科学提示希望 Agent 完成的动作

| 阶段 | 要回答的问题 | 程序提供的信息 |
| --- | --- | --- |
| 观察 | 已知变体表现怎样，哪些现象值得检验？ | 当前方法的训练统计、较高/较低/中间分数例子 |
| 假设 | 在什么序列背景下，哪个改变可能产生什么效果？ | 已知序列和有适用范围的知识规则 |
| 设计 | 哪些新候选可以探索改进或检验假设？ | 四位点空间和预算；v3仅在纠正时提供无标签替补 |
| 模型评估 | 哪些候选在当前预测器下较有希望？ | Python 实际评分并排序，LLM 不编造分数 |
| 反馈 | 上轮实际值与预测相差多少，原假设受到怎样的影响？ | 本方法刚获得的测量值、原预测与带符号残差 |
| 下一轮 | 哪些想法继续探索，哪些局部假设需要调整？ | 已揭示反馈、已测序列和有限失败摘要 |

“带符号残差”在这里定义为实际值减预测值。负值表示模型估计偏高，正值表示估计偏低。

## 输出内容

接口仍返回 `analysis` 和 `proposals` 两个字段，兼容原有本地评分流程。

- `analysis` 使用 Observations、Hypotheses、Feedback、Design 四个部分，写简洁、可检查的决策摘要。
- 每个候选包含 `variant`、`hypothesis`、`rationale`、`knowledge_rule_ids`。
- 假设应尽可能连接具体的已知序列背景，并说明怎样的观察会削弱该预期。
- 规则编号只引用本请求中提供的知识。基础 Agent 没有知识规则时使用空列表。
- 数据和知识是不同依据：边际统计不等于单点因果；保守替换或电荷变化不保证提高功能。

## 数量与纠正

每次请求的 schema 按需要的新候选数量设置数组长度；本地仍检查序列字母、去重、资格和规则编号。

纠正请求只要求剩余的新条目。程序已经保存有效项，模型不重复输出；已知、已接受、已拒绝的序列被明确列出。无标签替补示例仅供模型选择，程序不会把它们自动加入结果。

## 版本解释

v2 同时改变提示文字、当前已知数据的展示方式、反馈摘要和请求约束；v3进一步移除首次设计的候选名单并压缩上下文，对照按整体设计评价。完整提示文本会写入新实验记录，供以后检查。

v3已固定提示完成种子11、22、33的两种Agent各三轮验证，18轮均获得40个有效候选，并且首次回答没有预填候选可复制。随后完成三组固定状态的详细反馈消融，两条件仅改变逐条反馈与摘要。具体性能、用量和结论范围见[阶段验证结果](<../reports/validation-stage/验证结果.md>)；早期单种子试运行和v2负面结果见[提示词对照结果](<../提示词对照结果.md>)。

本项目没有在提示词中嵌入公开 GB1 最佳序列、隐藏标签或独立测试答案。外部论文用于说明方法和科学约束，具体候选依据当前实验记录提出。
